# Addendum (2026-09-07): post-archival correction to 0006_broker_auth.sql

Same session, same root cause, same fix as `whatsapp-webhook-ingress`
(F2)'s own addendum — see that file for the full explanation. This
capability's `0006_broker_auth.sql` had the identical `ALTER FUNCTION ...
OWNER TO dirus_tenant_resolver` pattern for all three of its resolver
functions (`dirus_resolve_broker_id_by_{email,magic_link,session}`), and
hit the identical `permission denied for schema public` failure the first
time it ran against a real non-superuser Neon connection.

Fixed in the same commit (`f82c669`) with the same temporary `GRANT
CREATE`/`REVOKE CREATE ON SCHEMA public` bracket around each of the three
`ALTER FUNCTION ... OWNER TO` statements. Same justification for editing in
place: `0006` had never been successfully applied to any real, persistent
database before this fix — this was, in fact, the very first live
migration run of this database's full 0000-0006 chain.

**A second, independent defect was found later the same day** (session
work on `fix-chatwoot-tenant-resolution`, F2.1): the `REVOKE ALL ...
FROM PUBLIC` statements for these same three functions also failed
silently — no exception, no log — leaving `PUBLIC` `EXECUTE` live on all
three in the developer's real database. This is a different Postgres
behavior (`REVOKE` does not error when the executing role lacks
grant-option provenance on the ACL entry) than the `ALTER OWNER` gap this
addendum documents, and was NOT fixed by `f82c669`. It was found and fixed
by F2.1's own migration `0007_chatwoot_account_resolution.sql` (step 5b) —
see that change's own tasks.md for the full record. `0006_broker_auth.sql`
itself was not touched a second time; the correction was applied forward,
in `0007`, exactly the pattern this addendum's own fix should have used
had a real deployed database already existed at the time.

No table, column, RLS policy, or grant scope changed by either fix. Each
function's security envelope (`SECURITY DEFINER`, owned by
`dirus_tenant_resolver`, `SET search_path = ''`, schema-qualified body,
bare-`uuid` return) is unchanged.
